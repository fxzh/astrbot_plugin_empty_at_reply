# QQ官方机器人空@响应（astrbot_plugin_empty_at_reply）

单独 @ 机器人（不带任何内容）时，让机器人也正常回复。

## 问题根因

QQ 官方机器人（`qq_official` 适配器）平台上，空 @ 消息被三层逻辑叠加吞掉：

1. **适配器层**：`qqofficial_platform_adapter.py` 解析消息时会**无条件**追加
   一个 Plain 文本段（即使内容为空），空 @ 的消息链恒为 `[At, Plain("")]`；
2. **内置空@等待**：`builtin_stars/astrbot/main.py` 的 `handle_empty_mention`
   只在消息链**恰好只有一个段且是 @** 时触发（`len(messages) != 1` 直接返回），
   两段形态永远不满足——即使配置里 `空@触发等待` 已开启；
3. **LLM 阶段**：`process_stage/.../internal.py` 发现 `message_str` 为空、
   无媒体无引用时直接跳过请求。

结果：@ 机器人不说话 → bot 毫无反应。

## 解决方式

插件挂最高优先级（`priority=sys.maxsize`，先于内置的 `maxsize-1`），
在唤醒检查之后接管空 @ 消息，把它重摆成「@ + 一句话」的普通消息形状：

- `message_str` 非空 → 通过 LLM 阶段的空消息检查；
- 两个消息段 → 绕开内置「空@等待」的 `len==1` 判断，避免双重处理；
- 走正常流程，**带着完整对话上下文**回复，与普通 @ 消息完全一致。

判断很保守：消息里只要有实际文本、引用、图片、文件、语音、视频、
表情、@ 别人等其他内容，插件一律不接管，走原生流程。

### 等待窗口（可选，默认开启）

回复后的一段时间内（默认 60 秒），触发空 @ 的那位用户的下一条消息
（无需再 @）会作为正式内容继续对话。按发送者限定，同群其他人的消息
不会被误抓（适合共享上下文的群聊场景）。

## 配置

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| enabled | true | 总开关 |
| placeholder_text | 空 | 空 @ 时交给模型的占位文本；留空自动用「@机器人昵称」。支持变量：`{name}`=机器人称呼（按消息动态取）、`{sender}`=触发者昵称，如 `@{name}（{sender}仅仅at了你一下）`；不含变量时整段原样使用 |
| bot_fallback_name | bot | 拿不到机器人昵称时的兜底称呼 |
| wait_followup | true | 回复后开启等待窗口 |
| wait_seconds | 60 | 等待窗口时长（秒），1-600 |

## 安装

把本目录放到 AstrBot 数据目录的 `data/plugins/` 下（或通过 WebUI
「插件市场 → 离线安装」导入），然后在 WebUI 插件页重载/重启生效。

## 兼容性

- 在 AstrBot v4.29.3（桌面版）源码上核对编写；
- `qq_official` 平台为主战场，其他平台（aiocqhttp 等）的 `[At]` 单段
  空 @ 形态同样兼容（会先于内置空@等待接管）；
- 不要与其他接管空 @ 流程的插件（如 empty_mention_plus）同时开启，
  容易叠加两层等待。
